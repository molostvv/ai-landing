# Staff Agent — staff-agent.ru

Информационный сайт о цифровых сотрудниках: ИИ-агентах, которым поручают часть работы. Без CMS и базы данных. Статьи хранятся в markdown-файлах, PHP-скрипт собирает из них статичные HTML-страницы, nginx их отдаёт. Бэкап — этот git-репозиторий, включая конфиги nginx в `deploy/`.

Сайт служит полигоном для системы SEO-агентов (отдельный проект `seo-department`). Поэтому любое изменение проходит через git и согласование.

## Структура

| Путь | Что это |
|---|---|
| `content/home.md` | Текст главной страницы |
| `content/articles/*.md` | Статьи. Имя файла — адрес страницы: `kak-nastroit-agenta.md` → `/kak-nastroit-agenta/` |
| `content/articles/_example.md` | Образец оформления статьи. Файлы на `_` на сайт не попадают |
| `content/pages/*.md` | Страницы «О проекте» и «Политика конфиденциальности» |
| `content/img/` | Картинки для статей, на сайте — `/img/…` |
| `settings.php` | Название, адрес сайта, номер счётчика Метрики, автор |
| `build.php` | Сборка и проверки |
| `templates/` | PHP-шаблоны страниц |
| `assets/` | CSS и иконка |
| `lib/` | Вспомогательные функции и [Parsedown](https://github.com/erusev/parsedown) 1.7.4 (markdown → HTML, лицензия MIT) |
| `public/` | Собранный сайт, в git не хранится |

## Как добавить статью

1. Скопировать `content/articles/_example.md` в `content/articles/<адрес-латиницей>.md`.
2. Заполнить шапку: `title`, `description`, `date`, `status: draft`.
3. Написать текст в markdown, начиная с `## …`: заголовок H1 берётся из `title`.
4. Проверить сборкой и посмотреть локально (см. ниже).
5. Опубликовать: поменять `status` на `published`. Делает это только владелец или агент по явной команде владельца.

## Сборка и просмотр

```bash
php build.php                       # предпросмотр: сайт закрыт от индексации, Метрика выключена
php -S localhost:8000 -t public     # открыть http://localhost:8000
php build.php --prod                # боевая сборка для адреса из settings.php
```

Сборка останавливается и не трогает `public/`, если:

- в шапке нет обязательного поля, неверная дата или статус;
- в тексте есть заголовок `# …` (второй H1);
- имя файла не латиницей или адрес занят;
- на странице ссылка на несуществующую страницу сайта;
- в готовом HTML осталась заглушка `{{…}}`;
- подключена Метрика, а политика конфиденциальности не опубликована.

Предупреждения (сборку не останавливают): `title` длиннее 70 символов, `description` не в пределах 70–170, дата публикации в будущем.

На каждый push GitHub Actions повторяет боевую сборку, проверяет синтаксис PHP, HTML (валидатор W3C) и ищет секреты (gitleaks).

## Что выдаёт сборка

- Страницы с `title`, `description`, `canonical` (в боевой сборке), Open Graph и разметкой Schema.org: `WebSite`, `BlogPosting`, `BreadcrumbList`.
- Оглавление в статье, если в ней от трёх разделов `## …`, и блок «Читайте также».
- `sitemap.xml` с датами изменения, `robots.txt` (в предпросмотре — запрет индексации), страницу `404.html`.
